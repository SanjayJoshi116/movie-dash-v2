# CLAUDE.md

Guidance for Claude Code (or any AI agent) working in this repo.

## Stack
- Frontend: React 19, TypeScript 6, Vite 8 (Rolldown), Ant Design v6, Chart.js 4 (+ react-chartjs-2, chartjs-chart-matrix), React Router v8 (import from `'react-router'` — `react-router-dom` is deprecated/frozen at 7.18.1 as of v8; the base package now includes the DOM bindings, `react-router-dom` was just `export * from "react-router"`).
- Backend: Express 5 (TypeScript, run via `tsx`; `express-rate-limit` 8), serves movie data from a local CSV via `csv-parser`. Uses `axios` (not native `fetch`) for outbound TMDB calls — see Architecture below for why.
- Testing: Playwright E2E (`tests/app.spec.ts`, 135 tests, 13 suites: Dashboard, Movies, Movies Grid View, Movies Grid Sort, Movies Advanced Filters, Movies Add & Delete, Navigation, Mobile, Stats Page, Theme, Filter Persistence, Edge Cases, Drill-down consistency; shared helpers in `tests/helpers.ts`) + server API tests (`server/__tests__/*.test.ts`, 118 tests, Node's built-in `node:test` via `tsx --test` — no Jest/Vitest) + frontend unit tests (`tests/unit/*.test.ts`, 56 tests, `node:test` via `tsx --test`, covering `src/utils` display, range-slider and CSV-escaping helpers plus the chart click/cursor handlers; excluded from Playwright via `testIgnore: ['unit/**']`) + Python tool tests (`tests/python/`, 42 tests, stdlib `unittest`).
- Lint: ESLint (`eslint.config.mjs` — typescript-eslint, react-hooks, unused-imports).
- TypeScript is pinned `~6.0.3`: typescript-eslint 8 supports only `<6.1.0`, which blocks TypeScript 7. No change is open for it (`upgrade-typescript-7` was dropped 2026-11-14): propose one once `npm view typescript-eslint peerDependencies` allows 7. TS 6 defaults `types` to `[]`, so each tsconfig lists its globals (root `vite/client`, which also types `import './x.css'`; server `node`). Add a new global-types package there or its globals vanish. `server/tsconfig.json` uses `module`/`moduleResolution: "node16"`, and still emits CommonJS because package.json has no `"type"`.

## Commands
- `npm run dev` — Vite (port 3000, `localhost` only) + Express (port 5000, `127.0.0.1` only) concurrently. `npm run dev:lan` is the same with `vite --host`, so the web app is reachable on the LAN. Port 5000 stays loopback, but Vite's `/api` proxy lets LAN devices use the whole API (list/add/delete), so it's for trusted networks only. Vite has `strictPort: true`: a busy 3000 fails `npm run dev` rather than moving to 3001.
- `npm run build` — `tsc --noEmit && tsc -p tsconfig.node.json && vite build` (typecheck + production build). `tsconfig.node.json` type-checks `tests/`, `playwright.config.ts` and `vite.config.ts` (Node types), which Playwright/Vite would otherwise only strip; `npm run type-check` runs both projects.
- `npm run check:bundle` — after `build`: `scripts/check-bundle.mjs` (plain Node + built-in `zlib`, no network) reads `dist/.vite/manifest.json`, walks the `index.html` entry's **static** `imports` (never `dynamicImports`) and fails if that landing-route JS is over 400 kB gzip, or if any `dist/assets/*.js` is over 500 kB minified (matches `build.chunkSizeWarningLimit: 500`). Prints a per-chunk table.
- `npm start` — `build` + `build:server` + `server:prod`: the whole app (built SPA + `/api`) on one port, http://localhost:5000.
- `npm run lint` — `eslint . --max-warnings 0` (any warning fails). `eslint.config.mjs` uses ESLint's `defineConfig` (not the deprecated `tseslint.config`) and ignores gitignored `**/*.tmp.*` throwaways.
- `npm run test:e2e` — Playwright headless (needs `src/movies.csv` present, see Data below). `retries` is `0` locally and `1` only under `CI` (`trace: 'on-first-retry'`), so local flakiness isn't masked; `forbidOnly` is on under `CI`, so a committed `test.only` fails the run. Specs import `test`/`expect` from `tests/helpers.ts`, not `@playwright/test`: its guard (on the browser *context*, so it covers `page` and any page the test opens) aborts every non-GET `/api` request and every `/api/tmdb/*` call unless the test `page.route`-mocks it (page routes run before the context guard) (`mockMovies()` for `GET /api/movies`), so e2e can never write the real CSV — lint enforces this (`@typescript-eslint/no-restricted-imports` on `tests/**/*.spec.ts`, type-only imports allowed). API calls aren't routed: the `request` fixture is GET-only (write methods throw), and lint bans `.request.post/put/patch/delete/fetch` (dot or `['post']` access), `newContext` and `browser.newPage` in `tests/` — `fetchMovies` (`page.request.get`) is the only API use. `tests/helpers.ts` also has `chartCanvas(page, title)` (Stats) / `dashboardChartCanvas(page, title)`, `confirmDrawerDelete(page)`, `codesByLanguageName(movies)`, `filterChip(page, text)`, `searchResult(modal, text?)`, `exportCsv(page)` (the downloaded CSV's text), `columnCells(page, header)` (table cells by header text — no `td:nth-child`) and `FILTERS_STORAGE_KEY` (re-exported from `usePersistedFilters`) — use them rather than re-inlining the selectors or the key. `selectInDrawer(label, option)` matches the option's title exactly and arrow-keys the virtual list until it renders (arrowing works for every Select alike; Language also searches labels since B177, via `optionFilterProp="label"`). No `waitForTimeout` (lint-banned in `tests/`) — use web-first assertions (`expectTotal()`, `toHaveCount`, `expect.poll`); assertions are dataset-agnostic (derived from `fetchMovies()` / mocked rows) so the suite passes on both the real CSV and the 5-row template.
- `npm run test:server` — server API tests; each test runs `createApp()` against a CSV in its own OS temp dir and **never touches `src/movies.csv`**. TMDB is stubbed (`stubTmdb()` in `server/__tests__/helpers.ts`), so no network/API key needed. Start servers with `const start = serverPool();` (closes them all in the file's `after`); `errnoError(code)` and `sleep(ms)` live in the same helpers file, plus `reached()` (`{ promise, hit }`: a stub or fs hook calls `hit()` at the point the test must wait for — never `sleep()` and hope) and `isPending(p)` (a `setImmediate` race, for "still not settled" checks). A test that injects a fault asserts that it fired (e.g. `armedStat`'s `fired` in `hardening.test.ts`); `server/tsconfig.test.json` type-checks `server/__tests__` (no emit); `npm run type-check:server` runs it after `server/tsconfig.json`, so CI covers it. Fixtures are built in code, not checked-in `.csv` files, because `core.autocrlf` would rewrite their line endings/trailing newlines.
- `npm run test:unit` — frontend unit tests (`tsx --test tests/unit/*.test.ts`, `node:test` + `node:assert/strict`, no browser/server) for the shared `src/utils` helpers (`formatRevenue`, `withAlpha`, `formatDateDDMMYYYY`, `getLanguageName`, `groupByField`, `topNWithOther`, buckets, `alignToStep`/`niceStep`/`computeFilterSpans`, `sanitizeCsvValue`/`unsanitizeCsvValue`/`escapeCsvField` (one case table, round trip included), `clickHandlers`/`NOT_CLICKABLE`). New pure-helper tests go here; `tsconfig.node.json` type-checks them.

## Architecture
- `src/contexts/MoviesContext.tsx` — single source of truth for movie data; fetched once at app root via `useMoviesContext`/`useMovies`. Don't re-fetch per component. `loading` means *first load only* (drives `LoadingError`'s full-page skeleton); `refetch()` after the first load sets `refreshing` instead and failures go to `refreshError` (TopBar shows a spinner / a retry button), keeping the last data on screen. Don't make `refetch()` set `loading` again — the skeleton swap unmounts the page, wiping the Add Movie modal's results and the table's sort/page. The context value is `useMemo`'d. Each fetched row goes through `normalizeMovie()`: every `CATALOGUE_COLUMNS` key becomes a string (`''` when missing or not a string; extra keys kept), so a short row or a missing column can't crash a `.split`/`localeCompare` anywhere — don't add per-site guards for that, and don't move it into the server (it serves only the columns on disk). `refetch()` returns a promise that settles (never rejects) when that load finishes; the route `ErrorBoundary`'s "Try Again" waits on it before re-rendering.
- **Chunking / bundle budget** (`vite.config.ts` `build.rolldownOptions.output.codeSplitting.groups`, openspec `frontend-performance`). Landing JS was about 517 kB gzip with a 988 kB `vendor-antd` chunk; it's now about 332 kB gzip (Vite 8 + antd 6). Vite 8 deprecates Rollup's `manualChunks`; each group has a `test` regex and a `priority` (react 4 > charts 3 > antd-core 2 > antd-shell 1) — a module two groups could claim goes to the higher priority, which keeps the graph acyclic. Path regexes use `[\/]` so they match on Windows.
  - Named chunks: `vendor-react` (react/react-dom/react-router/scheduler), `vendor-charts` (chart.js/react-chartjs-2/chartjs-chart-matrix/@kurkle/color), `vendor-antd-core` (root `antd/es/config-provider/index.js`), and `vendor-antd-shell` (`ANTD_EVERY_ROUTE`: the antd components *every* route uses — the shell's plus Typography/Card).
  - Rolldown moves a group's tree-shaken dependency closure into its chunk too (like Rollup's `manualChunks` did), so these two stay closed (graph: react ← core ← shell ← index ← routes, no cycles) without listing antd internals.
  - Everything else, including Table/Drawer/Slider/Modal, matches no group, so Rolldown places it per route. **Don't go back to one `vendor-antd` chunk**: it shipped every component on the Dashboard. Only add a component to `ANTD_EVERY_ROUTE` if all routes load it; anything else would be forced onto the landing page.
  - Rooting an *app* module (e.g. `Dashboard.tsx`) doesn't work: app files import the `antd` barrel, so the closure becomes all of antd (957 kB).
  - `Dashboard.tsx` lazy-loads `MovieDrawer` with `retryableLazy()` (like the routes, below). It's mounted on first open (render-phase `drawerMounted` flag) and kept mounted afterwards so the close animation plays. It sits in a `ChunkErrorBoundary` (`src/components/ChunkErrorBoundary.tsx`, renders `null` + calls `onError`): only a `ChunkLoadError` (a failed download, wrapped by `retryableLazy`) shows an inline error `Alert`, unmounts the drawer (dropping the failed boundary) and calls `retryFailedLazies()`, so the next open downloads again; the boundary rethrows any other error from `render`, so a drawer crash still reaches the route `ErrorBoundary` (don't match browser error messages instead, they differ per browser). Chromium fetches a failed module again; other browsers may cache the failure, so the `Alert` also has a "Reload page" action. It's an `Alert`, not antd `message`: `message` isn't on the landing route and added ~9 kB gzip to it.
  - The Movies/Stats routes load through `retryableLazy()` (`src/utils/retryableLazy.ts`), not bare `React.lazy`: a failed chunk download is wrapped in `ChunkLoadError` and queues a fresh `React.lazy`, applied by `retryFailedLazies()`, which App passes as the route `ErrorBoundary`'s generic `onClear` (run on mount and whenever it clears an error view: "Try Again", a newer `resetKey`) — never inside the rejection itself, or React's own re-render after the rejection starts another download forever. The boundary shows a chunk-load message plus "Reload page" for a `ChunkLoadError`.
  - Tabs is still in the landing chunks: antd's `Card` imports it (for `tabList`).
  - `check:bundle` guards this config; re-run it after any Vite/antd bump.
- **antd 6 notes** (`src/App.tsx` `ConfigProvider`): v6 made `Tag` `filled` with no trailing margin by default; the app restores the v5 look globally via `tag={{ variant: 'outlined', styles: { root: { marginInlineEnd: 8 } } }}` — don't re-style tags per call site. Two documented exceptions, both because a flex `gap` already spaces them: `MovieCardGrid`'s rating and genre tags set `margin: 0`, and `AddMovieModal`'s trailing "Added" tag sets `marginInlineEnd: 0` (so it lines up with the Import button it replaces). Use v6 prop names (`Alert title`/`closable.onClose`, `Drawer size`, `Modal destroyOnHidden`, `Descriptions`/`Statistic` `styles.*`), not the deprecated v5 ones. `List` is deprecated in v6 (removed in v7), so the app doesn't use it: Dashboard Recent Releases (an `Empty` "No dated releases" when no row has a parseable date) and AddMovieModal results are plain `<ul className="plain-list">` lists (`index.css`; named "Recent releases" / "Search results", e2e finds items by the `list`/`listitem` roles). Don't bring `List` back.
- `src/contexts/ThemeContext.tsx` — light/dark theme, saved to `localStorage` under `movieDash_theme` **only when the user toggles** (written in `toggleTheme`, never on mount, so an OS-derived default is never mistaken for a choice; reads/writes wrapped in try/catch — blocked storage must not crash the provider). Until a choice is saved (`hasChoice`), the theme follows `prefers-color-scheme`, including live OS changes (a `matchMedia` `change` listener, removed once the user chooses). The old bare `theme` key is neither read nor removed (its values were all written on mount, and on a shared `localhost` origin it may belong to another app); `playwright.config.ts` pins `colorScheme: 'dark'` so the e2e suite's dark-default assumptions stay deterministic. Before React mounts, `public/theme-init.js` (a blocking `<script src>` in `index.html` — a file, since the CSP is `script-src 'self'`) applies the same rule (saved choice, else OS, else dark) to `data-theme`, and an inline `<style>` in `index.html` paints the theme's base colour (`--export-bg`'s values) with `color-scheme`; keep all three in sync if the rule or the colours change. `index.css` sets `color-scheme` per theme and a `body` background.
- `src/pages/Dashboard.tsx` (`/`) is a summary landing page (stat cards, highlights, mini trend/genre/rating charts, recent releases, CTAs) built from `src/components/DashboardSection.tsx` (title + content wrapper, standardizes section spacing) — the filterable table/grid catalogue lives at `src/pages/Movies.tsx` (`/movies`). `FilterState` (`src/types/movie.ts`, with `DEFAULT_FILTERS` beside it) carries `directors`, `runtimeRange`, `revenueRange` alongside search/languages/genres/year/vote.
- `src/components/MovieCardGrid.tsx` is the card-grid alternative to `MovieTable.tsx`, toggled via `Segmented` on the Movies page. Column span is `xs={24} sm={12} md={8} lg={6} xl={4}` — 6 cards/row from 1200px up; keep the cover `<img>`'s `width: '100%'` alongside `height` when touching this so `objectFit: 'cover'` has a box to crop against. It has its own local sort control (name/year/rating/runtime, `sortMovies()`) independent of `MovieTable`'s column sorters — grid and table don't share sort state. Each card keeps `role="button"` + `aria-label="View details for X"` (the grid sort test reads it) and adds `aria-describedby` → its body wrapper `movie-card-<Movie ID>-details`, so the visible details are announced. `MovieTable`'s Language sorter compares `getLanguageName()` (what the cell shows), and a sort on a `responsive` column hidden at the current width is cleared render-phase (it would otherwise keep ordering the rows and the export unseen). `MovieTable`'s sort and pagination are *controlled* (component state, one `Table.onChange` handler — Ant itself resets to page 1 on a sort change), so they survive a catalogue refresh. Both views take `filtersKey` (JSON of the filters with the *debounced* search, built in `Movies.tsx`) and reset to page 1 when it changes via the render-phase prev-value pattern — a data refresh alone doesn't change it, so add/delete keeps the page. Both also report their on-screen order through `onDisplayedChange(rows)` into a ref in `Movies.tsx`, which is what Export CSV writes (`MovieTable` recomputes the order with the columns' own `sorter` functions, matching Ant's stable sort/negated descend). The file is `movies-filtered-N.csv` only while a search/filter is active (`filtersActive`), else `movies-N.csv` — sorting alone isn't filtering; the name is decided with the *debounced* search, like the rows. The Export button's hint is a Tooltip on the button plus `aria-describedby` → a `.visually-hidden` span, not a hover-only icon. `exportCsv.ts` writes a UTF-8 BOM (`String.fromCharCode(0xfeff)`, for Excel), then `CATALOGUE_COLUMNS` (`src/types/movie.ts`) plus any extra keys, with the same formula-injection guard as the server on header names as well as cells, and revokes the blob URL after a 1 s timeout (not right after `click()`) — both import it from `src/utils/csvEscape.ts` (pure TS, listed in `server/tsconfig.json` `include`), so there is one copy.
- Range sliders (FiltersDrawer's four, Stats' year range) use `src/components/RangeSlider.tsx`: live draft while dragging, `onCommit` from Ant's `onChangeComplete` (fires on release and per keyboard step), draft resynced render-phase when the committed value changes from outside. rc-slider shows (and reports on every commit) values aligned to `step`, so on commit an end whose new value equals the aligned committed value keeps its exact committed value (`alignToStep()` in `filterSpans.ts`, mirroring rc-slider's alignment) — moving one handle never rounds the other (a drill-down's `3.999` on the 0.1-step vote slider stays `3.999`). Handles can cross (rc-slider `allowCross` defaults to `true`) and values come back sorted, so `keepUntouched` matches by index first, then the other bound, each committed bound used once. The revenue slider's `step` is `niceStep(span / 100)` (1/2/5 × 10^k), so a key press moves a readable amount, not $1. Use it for any new range filter — a plain `Slider` `onChange` refilters/re-persists on every drag tick. Its required `label` names the handles "<label> minimum"/"<label> maximum" (`ariaLabelForHandle`). `src/utils/filterSpans.ts` (`computeFilterSpans`) is the single source of slider bounds; `Movies.tsx` also uses it with `clampFiltersToSpans` (once, after the first load, render-phase) to clamp restored ranges to the current data — a range with no overlap is left as-is so its chip stays visible.
- `src/hooks/usePersistedFilters.ts` persists the Movies page's `FilterState` to `sessionStorage` — restored data goes through `sanitizeFilters()` (per-field shape check; bad fields fall back to defaults instead of crashing on e.g. `genres: null`) (not `localStorage`) — deliberate: survives navigating away and back within the same tab, resets on a new tab or browser restart. Don't switch it back to `localStorage` without checking `tests/app.spec.ts`'s "Filter Persistence" suite still matches the intended reset behavior. The legacy `localStorage` cleanup has its own try, so blocked `localStorage` doesn't skip the `sessionStorage` restore. Its optional second param `preset` (a drill-down's `presetFilters`) becomes the *initial* state — sanitized, merged over the defaults, written to `sessionStorage` — so the saved filters never render first. The Movies search uses `useDebounce(value, delay, immediate?)` (`src/hooks/useDebounce.ts`): `immediate(v)` true applies the value render-phase, so clearing the search (`v === ''`) filters at once while typing stays debounced.
- `src/utils/poster.ts` exports `POSTER_FALLBACK` (a data-URI placeholder), used wherever a `Movie['Poster URL']` might be blank or fail to load. `Movie['Poster URL']` is optional — always fall back to it rather than conditionally omitting the image element. `src/components/PosterThumb.tsx` wraps the fallback-on-error `<img>` pattern itself (`movie`, `width`, `height`, optional `radius`/`style`) — `Dashboard.tsx`'s Highlight cards and Recent Releases list both use it; `MovieCardGrid`/`MovieDrawer` still inline their own `<img>` since their sizing/layout needs diverge more. Use `PosterThumb` for new poster spots that fit its plain fixed-box shape rather than re-inlining the fallback logic a third time.
- Movies page filtering: search is an always-visible `Input` in the page toolbar; category/range filters (language, genre, director, year, vote, runtime, revenue) live in `src/components/FiltersDrawer.tsx`, opened via a `Filters` button (badge dot when active) instead of an inline collapsible panel. `src/components/ActiveFilters.tsx` renders removable chips + "Clear all" directly on the page: a `role="list"` named "Active filters", each antd `Tag` a `listitem` holding a real `<button>` named "Remove <chip>" (`.chip-remove-button`) — not antd's `closable` icon, which is `tabIndex=-1` and named "Close". e2e finds chips with `filterChip(page, text)`. Shared chip-building/active-check logic lives in `src/utils/filterChips.ts` (`buildFilterChips`, `isFiltersActive`) so the toolbar badge and the chips row don't duplicate filter-state logic. `SEARCHABLE_FIELDS` + `matchesSearch()` (`src/utils/search.ts`, used by `Movies.tsx` and by `tests/helpers.ts`'s `searchMatchCount`, so e2e expectations can't drift) cover `Name`/`Director`/`Genres`/`Actors/Actresses`/`Production Company`/`Production Country`/`Release Year`; the search also separately checks `getLanguageName(movie.Language)` (`src/utils/languages.ts`) so typing a language name (not just its ISO code) matches too. Search is accent-folded (`foldForSearch`: NFD, combining marks dropped, lower-cased) on both sides — each movie's folded fields are cached per object (`WeakMap`) and the term folded once per search — and trimmed at match time (`matchesSearch`, `Movies.tsx`, `isFiltersActive`/the chip), so a whitespace-only search is no search; the input itself keeps exactly what was typed — add new searchable text fields to the array, but a derived/looked-up field like language needs its own `||` clause in `matchesSearch` since it isn't a raw `Movie` property.
- `Dashboard.tsx` renders an Ant `Empty` (`PRESENTED_IMAGE_SIMPLE`, "Go to Movies" CTA) in place of the stat cards/highlights/charts when `movies.length === 0`, instead of showing a page full of zeros — checked after the `LoadingError` wrapper's loading/error branches, so it only applies to a genuinely empty (not still-loading) dataset.
- `src/utils/chartTheme.ts` — shared design tokens: `getCardStyle(isDark)` builds the glass-card style from CSS custom properties (`var(--glass-bg/border/shadow)`, `src/index.css`) rather than hardcoding its own per-theme values, so every glass surface (Dashboard cards, `StatCard`, `Sidebar`/`TopBar`/`BottomNav`) stays in sync with one theme source; the `isDark` param is optional and kept only for call-site compatibility, it no longer branches internally. `StatCard` spreads `getCardStyle()` and only overrides the background (hero tint) and `borderTop` (accent); keep it that way rather than re-inlining the surface. Hover lift (`StatCard`, `MovieCardGrid`) is the CSS `.lift-on-hover` class in `src/index.css`, replacing Framer Motion (removed from the project):
  - `transform` transition with an overshoot `cubic-bezier(0.34, 1.56, 0.64, 1)` approximating the old spring, plus `translateY(-2px) scale(var(--lift-scale, 1.02))`. StatCard sets `--lift-scale: 1.03` inline.
  - The selector is `.ant-card.lift-on-hover` so it outranks antd's `:where()`-scoped `.ant-card-hoverable` transition, and it repeats that rule's box-shadow/border-color fades.
  - No `prefers-reduced-motion` handling; that's the same as before. The wrappers' text/tick/grid colours come from `chartInk(isDark)` (same file) — don't hardcode `rgba` in a wrapper. Chart colors come only from here — never hardcode hex in a chart dataset: single-series charts use one entry (`CHART_PRIMARY` = `CHART_PALETTE[0]`, or another fixed index), never the whole palette array (Chart.js cycles it, so unrelated bars repeat colors); signed values use `CHART_POSITIVE`/`CHART_NEGATIVE`; fills/heatmaps use `withAlpha(color, a)` (accepts `#RGB`/`#RRGGBB` only, throws a `TypeError` otherwise); leave `hoverBackgroundColor` unset (Chart.js derives it). Stat-card accent colors are not chart colors. `CHART_PALETTE` is an 8-color muted set (down from 15 bright ones) — category charts cap at 7 named slices + "Other" via `topNWithOther` (`statsHelpers.ts`), so don't grow the palette past that without also revisiting the grouping pattern. `SPACING` (`xs`4/`sm`8/`md`12/`lg`16/`xl`20/`xxl`24) and `FONT_SIZE` (`label`13/`body`14/`value`28/`hero`40) are the only spacing/font-size values worth naming — apply them only where a raw number already exactly matches one of these (don't snap an odd value like `10` or `17` to the nearest step, that's a silent visual change); `BottomNav.tsx` was audited and none of its raw numbers matched, so it intentionally still uses inline literals.
- `src/components/StatsTabs/*` — one component per Stats tab (Overview, People, Ratings, Runtime, BoxOffice, Explore), composed in `src/pages/Stats.tsx`. `Stats.tsx` also owns a global Release Year Range `Slider` (with a "Reset" button shown once narrowed from the full `[yearMin, yearMax]` span) and passes the year-filtered `movies` down to every tab, so scoping applies everywhere at once rather than per-tab. When the data's year span changes while Stats is mounted (a refetch), a render-phase `prevBounds` block clamps `yearRange` to it, resetting to `null` (full span, Reset hidden) if it no longer overlaps or now covers everything — unlike Movies, which keeps a non-overlapping range for its chip. Empty states: an empty catalogue shows an `Empty` + "Go to Movies" instead of the slider and tabs (as on the Dashboard); a range with no releases replaces only the `Tabs` with an `Empty` + "Reset range" (`activeTab`/`?tab=` untouched, so Reset shows the same tab). `src/components/StatsTabs/ChartBlock.tsx` is the shared card wrapper (title + PNG-download button) — all 6 tab files import it instead of each defining their own; the download button finds a `<canvas>` inside itself via `useEffect`/`querySelector` and only renders if one exists, so it doesn't show up on non-chart cards like `TopNExplorer`.
- `Stats.tsx`'s active tab is dual-sourced: initial state checks `location.state.tab` (drill-down clicks from Dashboard/Movies) first, then falls back to the `?tab=` URL search param, then `'overview'` — each candidate is validated against `TAB_KEYS`, so `?tab=bogus` shows Overview instead of an empty tab bar. A `useEffect` keeps `?tab=` equal to the shown tab (`{ replace: true }`, so tab switches don't spam history) from the first render — including right after a `location.state` hand-off or an invalid param — so the URL is shareable/reloadable immediately (writing the URL is an external-system sync, which is why an effect is fine here despite the no-state-sync-in-effects rule). `handleTabChange` only sets state.
- `src/components/Charts/*` — thin theme-aware wrappers around Chart.js chart types; each memoizes its `options` object via `useMemo` so an unrelated parent re-render doesn't update the chart. Callback props (`onElementClick`, `isClickable`, `formatValue`) are read at event time through `useLatest()` (`src/hooks/useLatest.ts`, a ref assigned in a layout effect), so the memo depends only on `isDark`, whether a handler/formatter exists, and layout flags (`compact`, multi-series) — callers can pass inline arrows and don't need `useCallback`. Never put a callback prop itself in the deps. `Charts/chartHelpers.ts` holds the shared `clickHandlers(latest)` (onClick/onHover) and `useClickHandlers({ onElementClick, isClickable })`, which every clickable wrapper spreads into its options (it is `{}` without a handler and changes only when one appears/disappears, so it is the one click value in the memo deps) and `formatNumber` (integers as-is, ≤2 decimals, `—` for missing; HorizontalBar's default tooltip and Scatter's). `LineChart` uses `interaction: { mode: 'index', intersect: false }` (hovering/clicking anywhere in a year's column targets it) and `cubicInterpolationMode: 'monotone'` (no overshoot); `BarChart`/`LineChart` hide the legend when there is a single dataset. - **TMDB integration** (`server/server.ts`): `process.loadEnvFile(path.join(process.cwd(), '.env'))` at boot (wrapped in try/catch — optional locally) loads `TMDB_API_KEY`, the same var `movie-search.py` uses.   - **Op queue + reload-if-changed.** Every catalogue op that reads-then-writes the file or swaps in-memory state — import, delete, *and* the reload check at the top of `GET /api/movies` — runs through `enqueue()` (a promise chain; one failure doesn't break it). Inside the queue each op first calls `reloadIfChanged()`, which compares the file's `stat` fingerprint (`mtimeMs`+`size`) to the last load/write and re-reads the CSV if another writer (`movie-search.py`, `backfill_posters.py`, a hand edit) touched it — so in-app deletes don't wipe externally-added rows. The GET reload is queued too on purpose: an unqueued reload could land between an import's append and its in-memory push and duplicate the row. Don't add a new mutating route without wrapping its critical section in `enqueue()` + `reloadIfChanged()`.

- `src/utils/formatDate.ts` (`formatDateDDMMYYYY`, trims its input; blank → `''`, so callers need no `.trim()` guard) — release dates render as `DD-MM-YYYY` in `MovieTable`/`MovieDrawer`/Dashboard (highlights, Recent Releases)/`TopNExplorer`; use it for any new UI surfacing `Release Date` rather than printing the raw `YYYY-MM-DD` CSV value.

## Data
- `src/movies.csv` is gitignored and never committed — it's the user's own dataset (TMDB-sourced, see README). It won't exist in a fresh checkout.
- `public/movies.template.csv` is the committed template — copy it to `src/movies.csv` to get a working local dataset (a handful of rows) for dev/testing.
- **Canonical CSV value format** (`openspec/specs/catalog-data-format/spec.md`): `Genres`, `Actors/Actresses`, `Production Company`, `Production Country` are *all* names joined with `, ` (countries as full names, e.g. `United Kingdom, United States of America`, never ISO codes); a missing value is an **empty** field, never a placeholder. All three writers (in-app import, `movie-search.py` via its `field()` helper, the README mapping table) follow this. The list has no escaping, so a comma inside one name is replaced by a space before joining (B147: `joinNames()` in `server/app.ts`, `catalogue_io.join_names()`; a Python test checks both use the same rule); existing rows aren't rewritten. The server's loader (`normalizeStoredValue()` in `server/app.ts`) trims and lower-cases `Language` (B146: `EN`/` en` are `en` everywhere; a rewrite persists it) and reads a legacy exact-match `N/A` as `''` — the user's CSV had 79 of them (57 directors, 16 release years) from old `movie-search.py` runs — without rewriting the file (the next in-app delete rewrite will persist them as empty). `statsHelpers.groupByField` splits `Genres`/`Production Company`/`Production Country` on commas (`MULTI_VALUED_FIELDS`), so co-productions count toward each country; empty parts are skipped rather than bucketed as "Unknown". Add a field to `MULTI_VALUED_FIELDS` if you chart another comma-joined column.
- If `src/movies.csv` is missing, `server/server.ts` degrades gracefully (empty dataset, `ready: true`, no crash) — but Playwright e2e tests hard-require real rows (`tests/app.spec.ts` waits on `.ant-table-row`), so e2e will fail without a populated CSV. `.github/workflows/ci.yml` seeds it from `public/movies.template.csv` before running e2e.
- `movie-search.py` (Tkinter GUI, `pip install -r requirements.txt`) is an optional tool to search TMDB and append rows to `src/movies.csv` directly — kept for bulk/offline use alongside the in-app **Add Movie** modal (`src/components/AddMovieModal.tsx`, see Architecture above), which covers the common one-off-add case without leaving the browser. It reads `TMDB_API_KEY` from `.env` via `python-dotenv` — never hardcode the key back into the script; `.env` is gitignored, `.env.example` is the committed placeholder. It skips (doesn't update) rows whose `Movie ID` already exists in the CSV. `CSV_PATH` is anchored to the script's own directory (`os.path.dirname(os.path.abspath(__file__))`), not the process's working directory — don't reintroduce a bare `"movies.csv"` string, it'll silently write to the wrong file if the script is launched from elsewhere. The TMDB API key is always sent via `requests`' `params=`, never string-interpolated into a URL, and request-failure dialogs show a generic message rather than the raw exception (which could otherwise surface the URL/key on-screen).
- `backfill_posters.py` (repo root) — one-off script to fill `Poster URL` for existing `src/movies.csv` rows via TMDB lookup by `Movie ID`. Checkpoints every 100 rows; not part of the app runtime, run manually when needed. Each checkpoint re-reads the CSV and applies the posters found so far by `Movie ID` (`save_checkpoint`), so rows the app adds mid-run survive; a `401` stops the run, and a run that found nothing never rewrites the file.
- `catalogue_io.py` (repo root) owns **all** Python catalogue I/O, the TMDB session (`make_tmdb_session`) and the TMDB GET (`get_tmdb_object(session, api_key, path)` → `(status, data)`: status `None` on a network error, data `None` on any failure or a non-object body, no exception text escapes), mirroring the server's rules:
  - `read_catalogue` decodes `utf-8-sig`, records `bom`/`eol`/`(mtime_ns, size)` fingerprint, and reads header names like the server's `mapHeaders`: trimmed, cells blank after trimming are not columns (a rewrite drops them), and a repeated name raises `DuplicateHeaderError` (a `CatalogueHeaderError`) so neither script ever writes that file.
  - `append_row` writes by position (`Catalogue.layout`, `None` per blank header cell — same as the server's `csvLayout`) and escapes formula prefixes itself (`FORMULA_PREFIX_CHARS`, the same characters as `csvEscape.ts`'s `FORMULA_PREFIXES`; `test_formula_prefixes_match_typescript` fails if they differ), so callers pass raw values (never pre-escape: it would double the `'`; rows read from disk are never re-escaped). A new file's header is `CATALOGUE_COLUMNS` order, then extra keys; that tuple is a copy of `src/types/movie.ts`'s, kept equal by a unit test.
  - `append_row`/`add_row_if_new` add a missing trailing newline and use the file's EOL, and raise `CatalogueHeaderError` (never overwrite) for a non-empty file with no readable header. `add_row_if_new` re-checks the fingerprint right before appending and re-reads + re-checks duplicates if it moved, and always re-reads after a header migration (3 attempts).
  - `rewrite_catalogue` writes a unique `movies.csv.<pid>.<ns>.tmp`, keeps BOM/EOL, drops stray cells, raises `CatalogueChangedError` if the fingerprint moved, and `os.replace`s via `replace_with_retry` (Windows `PermissionError`, ~1.5 s). The sub-millisecond gap left between those checks and the write is accepted: the server takes no file lock.
  - Don't add a bare `open(CSV_PATH, "w")` or `encoding="utf-8"` read to either script — go through this module.
  - `movie-search.py`: every TMDB fetch (listing, a 10-page-capped language scan, save's one `append_to_response=credits,keywords` request per movie through a 5-worker pool) and the save's CSV appends run in `run_in_background` on a worker thread with no Tk calls; `root.after` polling delivers the result to the Tk thread, which owns every widget and dialog. Search/Save/Next/language are disabled meanwhile. Search state (`last_query`/`last_actor`/`current_page`/`total_pages`) changes only in `finish_listing`, so a failed or empty search keeps the shown list's paging. A TMDB `401` is reported as an API-key problem, not a connection one. Treeview cells come back as `int` for numeric text: wrap them in `str()`. The saved row is built from the fetched details only (`build_row`), never from Treeview cells. A save appends only when details, credits and keywords all succeeded. `root.mainloop()` runs only under `__main__`.
  - `backfill_posters.py`: a `finally` makes a best-effort checkpoint on any stop (Ctrl+C → exit 130, 401 → exit 1, unexpected errors propagate after it); `try_checkpoint` postpones on `CatalogueError`/`OSError` instead of crashing.
  - Tests: `tests/python/test_catalogue_io.py` (`python -m unittest discover -s tests/python`, stdlib only, bytes-level fixtures).

## Known gotchas
- **Windows process/port hygiene.** Stopping a background `npm run dev` by killing its shell (or Ctrl+C in some terminals) can orphan the node children (Vite, `tsx watch`). Orphans keep port 3000/5000 bound — Playwright (`reuseExistingServer` locally) then silently tests against the stale server (a non-Vite holder of 3000 now makes `npm run dev` fail fast via `strictPort`) — and Vite's file watcher holds directory handles that make `mv`/archive of folders fail with "Permission denied". Stop dev servers with `taskkill /PID <pid> /T /F` (whole tree), check `Get-NetTCPConnection -LocalPort 3000,5000` before e2e, and run e2e with `CI=1` when you need a guaranteed fresh server. If port 3000 is held by some *other* local project, don't kill it — run Playwright with a throwaway config (`playwright.tmp.config.ts`, gitignored) that starts `npx tsx server/server.ts` + `npx vite --port 3100 --strictPort` with `baseURL` on 3100. Ad-hoc verification specs go in `tests/*.tmp.spec.ts` (ad-hoc unit tests: `tests/unit/*.tmp.test.ts`; both gitignored) and are deleted after use; anything touching mutations must `page.route`-mock them, because a local run reads the user's real `src/movies.csv`.
- **The BOM escape (backslash-u-FEFF) gets mangled by editing tools.** AI Write/Edit tools — and `sed`, where backslash-u is a case modifier — have repeatedly turned that escape in BOM-stripping regexes/strings into a literal invisible U+FEFF character, which ESLint flags as `no-irregular-whitespace`. After touching `server/app.ts` or `server/__tests__/helpers.ts`, run `grep -n uFEFF` on them to confirm the escape text is intact; repair with a Node one-liner that builds it as `String.fromCharCode(92) + 'uFEFF'`.
- **StrictMode double-invoke + ref-gated effects.** `React.StrictMode` (enabled in `src/main.tsx`) mounts, cleans up, and remounts effects once in dev. Any effect that uses a ref to skip re-running "if nothing changed" (e.g. the stat-card count-up animation in `src/components/StatsTabs/OverviewTab.tsx`) must reset that ref in its cleanup function, or the synchronous remount will see "unchanged" and silently no-op — intervals/animations get cleared but never restarted. If you add a similar animated-counter or ref-gated effect elsewhere, apply the same pattern: clear the ref in cleanup. Also read `intervalsRef.current`/similar into a local `const` once at the top of the effect and reuse that variable in callbacks/cleanup, rather than re-reading `.current` in each closure — keeps every read inside one effect run pinned to the same ref snapshot.
- `useMoviesContext` (`MoviesContext.tsx`) and `useTheme` (`ThemeContext.tsx`) are hooks exported from the same file as their Provider component — that trips `react-refresh/only-export-components` (a file exporting both a component and a non-component breaks Fast Refresh's ability to hot-reload just the component). Both carry an `eslint-disable-next-line react-refresh/only-export-components` with a reason comment rather than being split into a separate file or refactored — matches this codebase's existing context-file layout.
- Don't reintroduce `as any` casts — `eslint.config.mjs` forbids `@typescript-eslint/no-explicit-any`. Use `as unknown as <ConcreteType>` when a third-party type (e.g. `chartjs-chart-matrix`'s `'matrix'` chart type) isn't in the base type registry.
- Ant Design keeps inactive `Tabs` panes mounted (but hidden) by default — a broad selector like `.anticon-info-circle` in a test/script can match hidden elements from other tabs. Scope selectors to the active pane when working within a specific tab — `activeTabPane()` (`tests/helpers.ts`, `getByRole('tabpanel')`; inactive panes are `aria-hidden`). Prefer role queries over antd class names in tests: antd 6 renamed `.ant-tabs-tabpane*` → `.ant-tabs-content*`, `.ant-tabs-content-holder` → `.ant-tabs-body-holder`, and single Select's `.ant-select-selector`/`.ant-select-selection-item` → `.ant-select-content` (the label is a bare text node there; `-content-value` only appears for options with their own style).
- **No `@media` queries anywhere in `src/`.** Responsive behavior is driven entirely by Ant Design's `Grid.useBreakpoint()` hook (see `src/App.tsx` — sidebar auto-collapses below the `md` breakpoint, 768px). `eslint-plugin-react-hooks`'s `react-hooks/set-state-in-effect` rule forbids syncing that hook's output into state via `useEffect`; use the render-phase pattern instead (compare current value to a `prevX` state, call `setState` directly in the render body when it differs) — see `App.tsx` for the working example.
