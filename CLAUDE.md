# CLAUDE.md

Guidance for Claude Code (or any AI agent) working in this repo.

## Stack
- Frontend: React 19, TypeScript, Vite 6, Ant Design v5, Chart.js 4 (+ react-chartjs-2, chartjs-chart-matrix), Framer Motion, React Router v8 (import from `'react-router'` — `react-router-dom` is deprecated/frozen at 7.18.1 as of v8; the base package now includes the DOM bindings, `react-router-dom` was just `export * from "react-router"`).
- Backend: Express (TypeScript, run via `tsx`), serves movie data from a local CSV via `csv-parser`. Uses `axios` (not native `fetch`) for outbound TMDB calls — see Architecture below for why.
- Testing: Playwright E2E (`tests/app.spec.ts`, 59 tests, 10 suites) + server API tests (`server/__tests__/*.test.ts`, Node's built-in `node:test` via `tsx --test` — no Jest/Vitest).
- Lint: ESLint (`eslint.config.mjs` — typescript-eslint, react-hooks, unused-imports).

## Commands
- `npm run dev` — Vite (port 3000) + Express (port 5000) concurrently.
- `npm run build` — `tsc --noEmit && vite build` (typecheck + production build).
- `npm run lint` — ESLint across the project.
- `npm run test:e2e` — Playwright headless (needs `src/movies.csv` present, see Data below).
- `npm run test:server` — server API tests; each test runs `createApp()` against a CSV in its own OS temp dir and **never touches `src/movies.csv`**. TMDB is stubbed (`stubTmdb()` in `server/__tests__/helpers.ts`), so no network/API key needed. Fixtures are built in code, not checked-in `.csv` files, because `core.autocrlf` would rewrite their line endings/trailing newlines.

## Architecture
- `src/contexts/MoviesContext.tsx` — single source of truth for movie data; fetched once at app root via `useMoviesContext`/`useMovies`. Don't re-fetch per component. `loading` means *first load only* (drives `LoadingError`'s full-page skeleton); `refetch()` after the first load sets `refreshing` instead and failures go to `refreshError` (TopBar shows a spinner / a retry button), keeping the last data on screen. Don't make `refetch()` set `loading` again — the skeleton swap unmounts the page, wiping the Add Movie modal's results and the table's sort/page. The context value is `useMemo`'d.
- `src/contexts/ThemeContext.tsx` — light/dark theme, persisted to `localStorage` (reads/writes wrapped in try/catch — blocked storage must not crash the provider). With no saved choice the first-visit theme follows `prefers-color-scheme`; `playwright.config.ts` pins `colorScheme: 'dark'` so the e2e suite's dark-default assumptions stay deterministic.
- `src/pages/Dashboard.tsx` (`/`) is a summary landing page (stat cards, highlights, mini trend/genre/rating charts, recent releases, CTAs) built from `src/components/DashboardSection.tsx` (title + content wrapper, standardizes section spacing) — the filterable table/grid catalogue lives at `src/pages/Movies.tsx` (`/movies`). `FilterState` (`src/types/movie.ts`) carries `directors`, `runtimeRange`, `revenueRange` alongside search/languages/genres/year/vote.
- `src/components/MovieCardGrid.tsx` is the card-grid alternative to `MovieTable.tsx`, toggled via `Segmented` on the Movies page. Column span is `xs={24} sm={12} md={8} lg={6} xl={4}` — 6 cards/row from 1200px up; keep the cover `<img>`'s `width: '100%'` alongside `height` when touching this so `objectFit: 'cover'` has a box to crop against. It has its own local sort control (name/year/rating/runtime, `sortMovies()`) independent of `MovieTable`'s column sorters — grid and table don't share sort state. `MovieTable`'s sort and pagination are *controlled* (component state, one `Table.onChange` handler — Ant itself resets to page 1 on a sort change), so they survive a catalogue refresh. Both views take `filtersKey` (JSON of the filters with the *debounced* search, built in `Movies.tsx`) and reset to page 1 when it changes via the render-phase prev-value pattern — a data refresh alone doesn't change it, so add/delete keeps the page. Both also report their on-screen order through `onDisplayedChange(rows)` into a ref in `Movies.tsx`, which is what Export CSV writes (`MovieTable` recomputes the order with the columns' own `sorter` functions, matching Ant's stable sort/negated descend). `exportCsv.ts` writes `CATALOGUE_COLUMNS` (`src/types/movie.ts`) plus any extra keys, with the same formula-injection guard as the server.
- Range sliders (FiltersDrawer's four, Stats' year range) use `src/components/RangeSlider.tsx`: live draft while dragging, `onCommit` from Ant's `onChangeComplete` (fires on release and per keyboard step), draft resynced render-phase when the committed value changes from outside. Use it for any new range filter — a plain `Slider` `onChange` refilters/re-persists on every drag tick. `src/utils/filterSpans.ts` (`computeFilterSpans`) is the single source of slider bounds; `Movies.tsx` also uses it with `clampFiltersToSpans` (once, after the first load, render-phase) to clamp restored ranges to the current data — a range with no overlap is left as-is so its chip stays visible.
- `src/hooks/usePersistedFilters.ts` persists the Movies page's `FilterState` to `sessionStorage` — restored data goes through `sanitizeFilters()` (per-field shape check; bad fields fall back to defaults instead of crashing on e.g. `genres: null`) (not `localStorage`) — deliberate: survives navigating away and back within the same tab, resets on a new tab or browser restart. Don't switch it back to `localStorage` without checking `tests/app.spec.ts`'s "Filter Persistence" suite still matches the intended reset behavior.
- `src/utils/poster.ts` exports `POSTER_FALLBACK` (a data-URI placeholder), used wherever a `Movie['Poster URL']` might be blank or fail to load. `Movie['Poster URL']` is optional — always fall back to it rather than conditionally omitting the image element. `src/components/PosterThumb.tsx` wraps the fallback-on-error `<img>` pattern itself (`movie`, `width`, `height`, optional `radius`/`style`) — `Dashboard.tsx`'s Highlight cards and Recent Releases list both use it; `MovieCardGrid`/`MovieDrawer` still inline their own `<img>` since their sizing/layout needs diverge more. Use `PosterThumb` for new poster spots that fit its plain fixed-box shape rather than re-inlining the fallback logic a third time.
- Movies page filtering: search is an always-visible `Input` in the page toolbar; category/range filters (language, genre, director, year, vote, runtime, revenue) live in `src/components/FiltersDrawer.tsx`, opened via a `Filters` button (badge dot when active) instead of an inline collapsible panel. `src/components/ActiveFilters.tsx` renders removable chips + "Clear all" directly on the page. Shared chip-building/active-check logic lives in `src/utils/filterChips.ts` (`buildFilterChips`, `isFiltersActive`) so the toolbar badge and the chips row don't duplicate filter-state logic. `SEARCHABLE_FIELDS` (`Movies.tsx`) covers `Name`/`Director`/`Genres`/`Actors/Actresses`/`Production Company`/`Production Country`/`Release Year`; the search also separately checks `getLanguageName(movie.Language)` (`src/utils/languages.ts`) so typing a language name (not just its ISO code) matches too — add new searchable text fields to the array, but a derived/looked-up field like language needs its own `||` clause since it isn't a raw `Movie` property.
- `Dashboard.tsx` renders an Ant `Empty` (`PRESENTED_IMAGE_SIMPLE`, "Go to Movies" CTA) in place of the stat cards/highlights/charts when `movies.length === 0`, instead of showing a page full of zeros — checked after the `LoadingError` wrapper's loading/error branches, so it only applies to a genuinely empty (not still-loading) dataset.
- `src/utils/chartTheme.ts` — shared design tokens: `getCardStyle(isDark)` builds the glass-card style from CSS custom properties (`var(--glass-bg/border/shadow)`, `src/index.css`) rather than hardcoding its own per-theme values, so every glass surface (Dashboard cards, `StatCard`, `Sidebar`/`TopBar`/`BottomNav`) stays in sync with one theme source; the `isDark` param is kept for call-site compatibility but no longer branches internally. `CHART_PALETTE` is an 8-color muted set (down from 15 bright ones) — category charts cap at 7 named slices + "Other" via `topNWithOther` (`statsHelpers.ts`), so don't grow the palette past that without also revisiting the grouping pattern. `SPACING` (`xs`4/`sm`8/`md`12/`lg`16/`xl`20/`xxl`24) and `FONT_SIZE` (`label`13/`body`14/`value`28/`hero`40) are the only spacing/font-size values worth naming — apply them only where a raw number already exactly matches one of these (don't snap an odd value like `10` or `17` to the nearest step, that's a silent visual change); `BottomNav.tsx` was audited and none of its raw numbers matched, so it intentionally still uses inline literals.
- `src/components/StatsTabs/*` — one component per Stats tab (Overview, People, Ratings, Runtime, BoxOffice, Explore), composed in `src/pages/Stats.tsx`. `Stats.tsx` also owns a global Release Year Range `Slider` (with a "Reset" button shown once narrowed from the full `[yearMin, yearMax]` span) and passes the year-filtered `movies` down to every tab, so scoping applies everywhere at once rather than per-tab. `src/components/StatsTabs/ChartBlock.tsx` is the shared card wrapper (title + PNG-download button) — all 6 tab files import it instead of each defining their own; the download button finds a `<canvas>` inside itself via `useEffect`/`querySelector` and only renders if one exists, so it doesn't show up on non-chart cards like `TopNExplorer`.
- `Stats.tsx`'s active tab is dual-sourced: initial state checks `location.state.tab` (drill-down clicks from Dashboard/Movies) first, then falls back to the `?tab=` URL search param, then `'overview'` — each candidate is validated against `TAB_KEYS`, so `?tab=bogus` shows Overview instead of an empty tab bar. A `useEffect` keeps `?tab=` equal to the shown tab (`{ replace: true }`, so tab switches don't spam history) from the first render — including right after a `location.state` hand-off or an invalid param — so the URL is shareable/reloadable immediately (writing the URL is an external-system sync, which is why an effect is fine here despite the no-state-sync-in-effects rule). `handleTabChange` only sets state.
- `src/components/Charts/*` — thin theme-aware wrappers around Chart.js chart types; each memoizes its `options` object via `useMemo` (keyed on `isDark` and any other props it reads) so an unrelated parent re-render doesn't force a full chart rebuild. `src/main.tsx` registers only the specific Chart.js controllers/elements/scales/plugins these wrappers actually use (not `registerables`) — if you add a new chart type or a new plugin option (e.g. `fill: true` needs `Filler`), register the matching piece in `main.tsx` too, or Chart.js throws at render time. `BarChart`, `LineChart`, `DoughnutChart`, `HorizontalBarChart`, and `PolarAreaChart` all accept an optional `onElementClick(index)` prop (wired to Chart.js's native `onClick`/`onHover` options) plus an optional `isClickable(index)` predicate — elements it rejects get no pointer cursor and no click (used for "Other"/"Unknown" slices, via `isDrillableLabel()`). The e2e drill-down tests rely on that cursor to locate bars on the canvas, so keep `onHover`'s pointer logic in sync with `onClick`; `RadarChart` and `MatrixChart` don't have it (low value for those chart shapes). `ScatterChart.tsx` follows the same wrapper pattern; its `ScatterController` is registered in `main.tsx` alongside the others (native Chart.js type, no `as unknown as` cast needed unlike `MatrixChart`'s third-party `matrix` type).
- `src/utils/statsHelpers.ts` — `groupByField`, revenue parsing/formatting helpers reused across stat tabs. `formatRevenue` is for aggregates/axes/slider/chip bounds: `0` → `$0`, negatives → `-$X`, only non-finite → `N/A` (don't use it to render a single movie's revenue, where 0 means *unknown*). `topNWithOther(data, MAX_NAMED_CATEGORIES = 7)` caps category charts at 7 named slices + "Other" so the 8-colour palette never repeats (the old threshold-based `withOther` is gone).
- **Drill-downs** (Dashboard + every Stats tab → `/movies` pre-filtered) all go through `useDrillDown()` (`src/contexts/DrilldownContext.tsx`), never a bare `navigate('/movies', { state: { presetFilters } })`. `Stats.tsx` wraps its tabs in `<DrilldownScopeProvider yearRange={yearRange}>`, so every Stats drill-down also carries the page's Release Year Range (a year/decade preset is *intersected* with it; an empty intersection doesn't navigate); outside the provider (Dashboard) drill-downs are unscoped. Labels "Other"/"Unknown" are never drill-down targets (`isDrillableLabel`).
- **Bucket ↔ filter consistency.** Bucketed charts (Dashboard rating, Ratings vote distribution, Runtime length) declare `Bucket[]` (`{ label, min, maxExclusive }`, half-open, last bucket `maxExclusive: Infinity`) once and use it for both `countIntoBuckets()` and the click's `bucketToRange(bucket, step, domainMax)`, which turns `[min, max)` into the Movies page's *inclusive* `[min, max − step]` (vote `step = VOTE_STEP` 0.001, the data's precision; runtime `step = 1`; open bucket → `domainMax`, i.e. 10 for votes / the dataset's max runtime). So a 4.0 rating counts in "4–6" and its "2–4" drill-down is `[2, 3.999]` — chips show those real bounds (`formatVote` trims to ≤3 decimals). Don't "fix" this by making the filter half-open: the user chose this over changing slider semantics. Vote `0` = unrated and revenue `≤ 0` = unknown: charts skip them and `Movies.tsx` excludes them *only while that range filter is active*, matching the existing missing-runtime rule.
- Dashboard's release trend is a continuous `TREND_YEARS` (10) span ending at the latest release year, zero-filling gaps (not "the last 10 years that have data").
- `server/app.ts` exports `createApp({ csvPath, tmdbApiKey, tmdb?, clientOrigin?, rateLimitPerMinute?, onBeforeLoad?, logger? })` → `{ app, ready }`; all routes and catalogue state live inside that factory closure (no module-level state), so tests can spin up isolated instances. `server/server.ts` is only the entry point: `loadEnvFile`, `createApp` with the `process.cwd()`-based CSV path, `listen`, signal handlers. `server/tmdb.ts` holds `createTmdbClient()` (axios + retries, injectable `sleep`/`httpGet`). New server files must be added to `server/tsconfig.json`'s `include` list or `build:server` won't emit them. Below, "`server/server.ts`" refers to the server as a whole — the route code is in `app.ts`.
- `server/server.ts` — Express API (`/api/health`, `/api/movies`, `/api/movies/:id`, `DELETE /api/movies/:id`, `GET /api/tmdb/search`, `POST /api/tmdb/import`), reads `src/movies.csv` on boot, gzip + cache headers. CSV path is resolved via `path.join(process.cwd(), 'src', 'movies.csv')` — **not** `__dirname` — because `__dirname` points at `server/` under `tsx watch` (dev) but at `server/dist/server/` once compiled (`server/tsconfig.json` has `rootDir: ".."`), which would silently resolve to a path that's never populated; both `npm run dev` and `npm run server:prod` are invoked from repo root, so `process.cwd()` is stable across both. Routes live under `/api` specifically so Vite's dev proxy (`vite.config.ts`, `/api` → `localhost:5000`) can't collide with client-side routes like `/movies` — a bare `/movies` proxy prefix would intercept the browser's page navigation to that route and return raw JSON instead of the SPA. Hardened with `helmet()`, `express-rate-limit` (300 req/min on `/api`), CORS restricted to `CLIENT_ORIGIN` env (defaults `http://localhost:3000` — set this in prod, don't widen back to open `cors()`), `Movie ID` param length validation, and a catch-all error-handling middleware (generic `500` JSON, no stack trace leak).
- **TMDB integration** (`server/server.ts`): `process.loadEnvFile(path.join(process.cwd(), '.env'))` at boot (wrapped in try/catch — optional locally) loads `TMDB_API_KEY`, the same var `movie-search.py` uses. All TMDB calls go through the `TmdbClient` from `createTmdbClient()` (`server/tmdb.ts`), which uses **axios**, not the native `fetch`/undici — undici was observed getting TLS-reset mid-handshake by AV/proxy HTTPS inspection on some Windows setups, consistently rather than transiently, so switching HTTP client (not just adding retries) was the actual fix. `tmdbGet()` also retries network errors and `429`/`5xx` (3 attempts, 500ms/1000ms backoff), mirroring `movie-search.py`'s `urllib3` `Retry`. `POST /api/tmdb/import` appends a row via `appendMovieToCsv()` — append-only, values mapped onto the header *currently on disk* (row fields with no matching column are dropped, it does **not** add columns), prefixes a `\n` if the file lacks a trailing newline, and refuses to append to a non-empty file whose header couldn't be read. `DELETE /api/movies/:id` has no append-only equivalent, so it uses `rewriteCsvFile(rows)` — regenerates the whole file, written to a unique `${csvPath}.<pid>.<ts>.tmp` then `fs.promises.rename()`d into place so a crash mid-write can't truncate `src/movies.csv` (`.gitignore`: `src/movies.csv*.tmp`); memory is swapped only after the write succeeds.
  - **Op queue + reload-if-changed.** Every catalogue op that reads-then-writes the file or swaps in-memory state — import, delete, *and* the reload check at the top of `GET /api/movies` — runs through `enqueue()` (a promise chain; one failure doesn't break it). Inside the queue each op first calls `reloadIfChanged()`, which compares the file's `stat` fingerprint (`mtimeMs`+`size`) to the last load/write and re-reads the CSV if another writer (`movie-search.py`, `backfill_posters.py`, a hand edit) touched it — so in-app deletes don't wipe externally-added rows. The GET reload is queued too on purpose: an unqueued reload could land between an import's append and its in-memory push and duplicate the row. Don't add a new mutating route without wrapping its critical section in `enqueue()` + `reloadIfChanged()`.
  - Import does its TMDB fetches *outside* the queue (never hold it across network I/O), with an `inFlightImports` set for an early `409`; the authoritative duplicate check re-runs inside the queue. TMDB `404` → `404`; CSV write failure → `500 "Failed to save movie"` (not reported as a TMDB error).
  - **Load-time normalization** (`loadCatalogue()`): strips a UTF-8 BOM from the header (`mapHeaders`) and un-escapes formula-guarded values (`'=`, `'+`, `'-`, `'@` → drop the `'`) so the UI shows the original text and each rewrite escapes it exactly once. `/api/movies` uses `Cache-Control: no-cache` + a weak `ETag` from `catalogueVersion` (bumped on every load/write) — don't go back to `max-age`, it made `refetch()` after add/delete serve a stale list. The error middleware passes body-parser `4xx`s (malformed JSON `400`, oversized `413`) through instead of `500`. Both helpers reuse `escapeCsvField`/`sanitizeCsvValue` (the latter guards against formula injection — `=`/`+`/`-`/`@` prefixes — same as `movie-search.py`'s `sanitize_csv_value`).
- `src/components/AddMovieModal.tsx` (opened from a button in `Movies.tsx`'s toolbar) — search TMDB by movie name and/or actor, optionally narrowed by a 4-digit release year, import a result via `POST /api/tmdb/import`, then calls `useMovies().refetch()` so the new row shows up without a page reload. `GET /api/tmdb/search`'s `year` param only applies (`/^\d{4}$/`-validated) if it parses as 4 digits — passed as `primary_release_year` to TMDB's `/search/movie`, or as a `release_date.slice(0,4)` equality filter when searching by actor credits (that endpoint has no year param of its own). `MovieDrawer.tsx` similarly gained a `Delete` button (`Popconfirm`-gated) calling `DELETE /api/movies/:id`, then `refetch()` + close.
- **Accessibility conventions** (accessible-ui spec): icon-only buttons need an `aria-label` (keep their `title` too — e2e selects the theme toggle by `button[title*="light mode"]`); never nest a `<Button>` in an `<a>` (use `<Button href download>`); decorative heading/tab emoji go in `<span aria-hidden="true">` — so headings' accessible names are emoji-free and e2e selects them as `getByRole('heading', { name: 'Movies', exact: true })`; colour-only state (e.g. the Filters badge dot) also goes in the accessible name (`"Filters, active"`). `MovieTable` rows are plain `<tr>`s (no `role="button"`/`tabIndex` — that broke table semantics): the Name cell renders a `.movie-name-button` `<button>` with no handler of its own — Enter/Space fire a native click that bubbles to the row's `onClick`. Chart PNG export (`ChartBlock`) composites the canvas onto the `--export-bg` token (per theme in `index.css`), since Chart.js canvases are transparent. `TopNExplorer` "Highest Rated" requires ≥50 votes (`MIN_VOTES_FOR_RATING`), dropping the cutoff when <10 movies qualify (template CSV); ranks 6–10 use `--text-secondary` (`--text-muted` is too faint on the light theme). `ErrorBoundary` is keyed on `location.pathname` (fresh boundary per route) and "Try Again" calls `onReset` (→ `refetch()`) first.
- `src/components/LoadingError.tsx` — shared skeleton-loading/error-alert wrapper (Ant `Skeleton`, not a bare `Spin`); `Dashboard.tsx`, `Movies.tsx`, `Stats.tsx` each wrap their page body in it instead of duplicating the same loading/error branch. Add new data-driven pages through this wrapper rather than reimplementing the loading/error branch.
- `src/components/BottomNav.tsx` — fixed bottom nav (Dashboard/Movies/Stats), rendered in `App.tsx` in place of `Sidebar` when `Grid.useBreakpoint().sm === false` — *strictly* false: `useBreakpoint()` is `{}` on the first render, and rendering BottomNav for `undefined` flashed it on desktop. Both navs match the active item via `normalizePath()` (`src/utils/path.ts`) so `/movies/` still highlights Movies. `TopBar` no longer takes a `title` prop — each page renders its own `<Title>` heading now that the header isn't the source of page identity on mobile.
- `src/utils/formatDate.ts` (`formatDateDDMMYYYY`) — release dates render as `DD-MM-YYYY` in `MovieTable`/`MovieDrawer`/Dashboard (highlights, Recent Releases)/`TopNExplorer`; use it for any new UI surfacing `Release Date` rather than printing the raw `YYYY-MM-DD` CSV value.

## Data
- `src/movies.csv` is gitignored and never committed — it's the user's own dataset (TMDB-sourced, see README). It won't exist in a fresh checkout.
- `public/movies.template.csv` is the committed template — copy it to `src/movies.csv` to get a working local dataset (a handful of rows) for dev/testing.
- **Canonical CSV value format** (`openspec/specs/catalog-data-format/spec.md`): `Genres`, `Actors/Actresses`, `Production Company`, `Production Country` are *all* names joined with `, ` (countries as full names, e.g. `United Kingdom, United States of America`, never ISO codes); a missing value is an **empty** field, never a placeholder. All three writers (in-app import, `movie-search.py` via its `field()` helper, the README mapping table) follow this. The server's loader (`normalizeStoredValue()` in `server/app.ts`) reads a legacy exact-match `N/A` as `''` — the user's CSV had 79 of them (57 directors, 16 release years) from old `movie-search.py` runs — without rewriting the file (the next in-app delete rewrite will persist them as empty). `statsHelpers.groupByField` splits `Genres`/`Production Company`/`Production Country` on commas (`MULTI_VALUED_FIELDS`), so co-productions count toward each country; empty parts are skipped rather than bucketed as "Unknown". Add a field to `MULTI_VALUED_FIELDS` if you chart another comma-joined column.
- If `src/movies.csv` is missing, `server/server.ts` degrades gracefully (empty dataset, `ready: true`, no crash) — but Playwright e2e tests hard-require real rows (`tests/app.spec.ts` waits on `.ant-table-row`), so e2e will fail without a populated CSV. `.github/workflows/ci.yml` seeds it from `public/movies.template.csv` before running e2e.
- `movie-search.py` (Tkinter GUI, `pip install -r requirements.txt`) is an optional tool to search TMDB and append rows to `src/movies.csv` directly — kept for bulk/offline use alongside the in-app **Add Movie** modal (`src/components/AddMovieModal.tsx`, see Architecture above), which covers the common one-off-add case without leaving the browser. It reads `TMDB_API_KEY` from `.env` via `python-dotenv` — never hardcode the key back into the script; `.env` is gitignored, `.env.example` is the committed placeholder. It skips (doesn't update) rows whose `Movie ID` already exists in the CSV. `CSV_PATH` is anchored to the script's own directory (`os.path.dirname(os.path.abspath(__file__))`), not the process's working directory — don't reintroduce a bare `"movies.csv"` string, it'll silently write to the wrong file if the script is launched from elsewhere. The TMDB API key is always sent via `requests`' `params=`, never string-interpolated into a URL, and request-failure dialogs show a generic message rather than the raw exception (which could otherwise surface the URL/key on-screen).
- `backfill_posters.py` (repo root) — one-off script to fill `Poster URL` for existing `src/movies.csv` rows via TMDB lookup by `Movie ID`. Rewrites the CSV with a checkpoint every 100 rows; not part of the app runtime, run manually when needed. Both Python scripts write full rewrites (backfill checkpoints, `movie-search.py`'s header migration) to `CSV_PATH + ".tmp"` then `os.replace()` — keep it that way, a bare `open(CSV_PATH, "w")` truncates the user's only copy if interrupted.

## Known gotchas
- **Windows process/port hygiene.** Stopping a background `npm run dev` by killing its shell (or Ctrl+C in some terminals) can orphan the node children (Vite, `tsx watch`). Orphans keep port 3000/5000 bound — Playwright (`reuseExistingServer` locally) then silently tests against the stale server — and Vite's file watcher holds directory handles that make `mv`/archive of folders fail with "Permission denied". Stop dev servers with `taskkill /PID <pid> /T /F` (whole tree), check `Get-NetTCPConnection -LocalPort 3000,5000` before e2e, and run e2e with `CI=1` when you need a guaranteed fresh server. If port 3000 is held by some *other* local project, don't kill it — run Playwright with a throwaway config (`playwright.tmp.config.ts`, gitignored) that starts `npx tsx server/server.ts` + `npx vite --port 3100 --strictPort` with `baseURL` on 3100. Ad-hoc verification specs go in `tests/*.tmp.spec.ts` (gitignored) and are deleted after use; anything touching mutations must `page.route`-mock them, because a local run reads the user's real `src/movies.csv`.
- **The BOM escape (backslash-u-FEFF) gets mangled by editing tools.** AI Write/Edit tools — and `sed`, where backslash-u is a case modifier — have repeatedly turned that escape in BOM-stripping regexes/strings into a literal invisible U+FEFF character, which ESLint flags as `no-irregular-whitespace`. After touching `server/app.ts` or `server/__tests__/helpers.ts`, run `grep -n uFEFF` on them to confirm the escape text is intact; repair with a Node one-liner that builds it as `String.fromCharCode(92) + 'uFEFF'`.
- **StrictMode double-invoke + ref-gated effects.** `React.StrictMode` (enabled in `src/main.tsx`) mounts, cleans up, and remounts effects once in dev. Any effect that uses a ref to skip re-running "if nothing changed" (e.g. the stat-card count-up animation in `src/components/StatsTabs/OverviewTab.tsx`) must reset that ref in its cleanup function, or the synchronous remount will see "unchanged" and silently no-op — intervals/animations get cleared but never restarted. If you add a similar animated-counter or ref-gated effect elsewhere, apply the same pattern: clear the ref in cleanup. Also read `intervalsRef.current`/similar into a local `const` once at the top of the effect and reuse that variable in callbacks/cleanup, rather than re-reading `.current` in each closure — keeps every read inside one effect run pinned to the same ref snapshot.
- `useMoviesContext` (`MoviesContext.tsx`) and `useTheme` (`ThemeContext.tsx`) are hooks exported from the same file as their Provider component — that trips `react-refresh/only-export-components` (a file exporting both a component and a non-component breaks Fast Refresh's ability to hot-reload just the component). Both carry an `eslint-disable-next-line react-refresh/only-export-components` with a reason comment rather than being split into a separate file or refactored — matches this codebase's existing context-file layout.
- Don't reintroduce `as any` casts — `eslint.config.mjs` forbids `@typescript-eslint/no-explicit-any`. Use `as unknown as <ConcreteType>` when a third-party type (e.g. `chartjs-chart-matrix`'s `'matrix'` chart type) isn't in the base type registry.
- Ant Design keeps inactive `Tabs` panes mounted (but hidden) by default — a broad selector like `.anticon-info-circle` in a test/script can match hidden elements from other tabs. Scope selectors to `.ant-tabs-tabpane-active` when working within a specific tab.
- **No `@media` queries anywhere in `src/`.** Responsive behavior is driven entirely by Ant Design's `Grid.useBreakpoint()` hook (see `src/App.tsx` — sidebar auto-collapses below the `md` breakpoint, 768px). `eslint-plugin-react-hooks`'s `react-hooks/set-state-in-effect` rule forbids syncing that hook's output into state via `useEffect`; use the render-phase pattern instead (compare current value to a `prevX` state, call `setState` directly in the render body when it differs) — see `App.tsx` for the working example.
